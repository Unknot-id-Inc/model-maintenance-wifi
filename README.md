# GUFU

There are several files for running the model.

- ```util.py``` provides utility functions for GUFU.
- ```graph.py``` provides the weighted graph formulations using network.
- ```gufu_data.py``` is the authoritative parser and prepared-data/artifact API; ```prep.py``` re-exports that API for compatibility.
- ```ae.py``` provides the feature extractor, checkpoint persistence, and ID-aligned encoder inference over ```PreparedDataset```.
- ```graph_build.py``` constructs and serializes deterministic typed sample/AP graph state from prepared data and learned AE features.
- ```sage_ve.py``` provides edge-feature GNN training, checkpoint loading, and ID-aligned inference over a shared ```GraphState```. Use cell 3 of ```gufu.py```; the old independent edgelist/random-feature entry point has been removed.
- ```lp.py``` predicts typed AP/sample edge deltas from a compatible ```GraphState``` and saved ```GNNFeatureArtifact```. It writes a separate result with a pure-apply graph snapshot; it does not read or overwrite an edgelist.
- ```lp_streaming.py``` provides an equivalent disk-backed link-prediction pass after exporting a compatible graph/GNN artifact bundle. It memory-maps features and CSR adjacency and streams scores/deltas to disk rather than retaining candidate-sized Python objects.
- ```fingerprint_update.py``` implements the no-vocabulary-change batch update: temporary combined-graph GNN fine-tuning, the two Section 5.2 MLPs and losses, Eq. (10) AE fine-tuning, and versioned RSS output keyed to original reference scans. The update MLP/AE/GNN states are saved together in a provenance-checked checkpoint.
- ```batch_transition.py``` projects incoming batches into the current AE vocabulary for shared-AP inference, preserves their complete raw AP data, predicts new AP edges, migrates AE columns/decoder rows by full BSSID, archives returning AP weights, re-exports final encoder/GNN features, and publishes an immutable versioned reference state.
- ```pred.py``` exposes bootstrap, one-batch update, sequential processing, immutable snapshots, resume validation, and a CLI under its main guard. The CLI and notebook call the same orchestration API.

The existing ```gufu.py``` is a Python-file notebook with nine ```# %%``` cells. It contains configuration and calls to shared APIs for preparation, AE, graph, GNN, link inspection, a one-batch demonstration, sequential update/resume, and optional evaluation. Set ```DATA_PROFILE="cpu_smoke"``` for the bounded CPU run over the checked-in ```fingerprint0.txt``` and ```fingerprint1.txt``` files; this uses one training epoch and omits virtual edges to keep the real-data smoke bounded. Set ```DATA_PROFILE="real_dataset"``` for the normal run and supply compatible checkpoints or explicitly select training. See ```docs/gufu_repair_plan.md``` for checkpoint contracts, exact instructions, validation scope, and paper-to-code assumptions.

The `gufu.py` default is `RUN_MODE="lp_streaming"`: run cells 1–8 to stream link prediction, process updates, and resume versioned batch snapshots without switching to the legacy expanded graph/delta path. Cell 7 commits the first selected update; cell 8 skips it and continues from that snapshot through the remaining inputs. Cell 9 is optional evaluation. This substantially reduces numeric working memory after the bootstrap graph/GNN artifacts exist, but bootstrap graph creation and prepared scan/RSSI objects are still in memory, so it is not a guarantee for graphs of arbitrary size. See `docs/streaming_link_prediction.md` for exact limits, run settings, and the streaming CLI. `stepwise` and `full` remain the in-memory alternatives.

Training APIs print scalar losses and stage metrics every 10 epochs by default, always including the final epoch. In ```gufu.py```, set ```LOG_EVERY_K_EPOCHS``` to change that cadence; direct training APIs accept ```log_every_epochs```, and the sequential CLI accepts ```--log-every-epochs K```.

The default bootstrap AE uses the repaired 32-D latent architecture with LeakyReLU, Kaiming-uniform convolution weights, and zero convolution biases. In `gufu.py` cell 1, set `AE_LOSS` to `"mean_squared_error"` or `"batch_frobenius_norm"` to choose the training objective. The notebook gives each objective a separate `RUN_ID` and checkpoint directory. Direct callers select the same values with `AETrainingConfig(loss=...)`. Checkpoints record the choice and history reduction; changing objective during checkpoint resume is rejected. MSE is mean-reduced across all dense entries, including missing-reading sentinels. Frobenius mode uses the raw norm of each minibatch residual and therefore its loss scale grows with minibatch size; its epoch history is the unweighted mean of those minibatch norms. The paper prints a Frobenius objective, while MSE remains a local alternative. Earlier ReLU architecture checkpoints are incompatible and must be retrained for the current pipeline.

The same cell exposes `AE_DROPOUT_PROBABILITY`, `AE_DENSE_WIDTH`, and `AE_LATENT_DIM`. The latent width may be any positive integer. GUFU appends two location inputs to each encoder vector, so graph/GNN/updater feature width is derived as `AE_LATENT_DIM + 2`; `OrchestrationConfig` rejects mismatched GNN widths. Checkpoints and run IDs record the dimension, and incompatible feature/checkpoint lineages are rejected. The published paper's AE uses a 32-D latent, so another width is a configurable local variant, not the paper's stated default. Changing dense width changes parameter shapes and requires fresh initialization; changing latent width requires a compatible full downstream model run.

The active GNN objective is also worth interpreting when reviewing its loss: Equation (4) sums `-log(ReLU(z_u · z_v))` over observed radio and virtual edges. It has positive attraction terms only, so its natural optimum is for incident normalized node embeddings to align; this can collapse the learned representation. The reduction is a sum, so its scale grows with the number of graph edges. Training dropout is applied before the node embeddings are normalized, making the printed training loss stochastic. See `docs/gufu_validation.md` for the inspection of the saved real-data run and the distinction between these effects.

Milestones 1–10 are implemented and validated on deterministic small fixtures. A bounded real-data smoke completed the pipeline on 392 bootstrap scans and one 2,078-scan update batch. This plumbing validation does not establish the paper's reported localization accuracy; the full real-data virtual-edge path and optional held-out evaluation remain unverified. RSSI agreement and localization metrics are separately named by ```gufu_evaluation.py```.

Paper-derived hyperparameters and local choices are recorded in ```docs/gufu_repair_plan.md```; not every current model choice exactly follows the paper.
